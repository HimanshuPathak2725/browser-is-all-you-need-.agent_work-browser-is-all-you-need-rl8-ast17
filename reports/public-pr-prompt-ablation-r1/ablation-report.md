# fmtlib prompt ablation and compiler-repair design

## Decision

Use the versioned `fmtlib-compiler-repair` lane. It restores the first prompt's
concrete C++ shapes, retains its task-specific 12-step migration, adds only eight
structural locks derived from actual compiler failures, and gives one sanitized
compiler-guided repair turn. The old r5/v2 contracts and hashes remain unchanged.

This is a retrospective observational ablation over one sample per historical
prompt, not a causal multi-seed study. It identifies prompt-correlated failure modes
and validates the new contract and harness deterministically; only a fresh matched
GCP run can measure model success.

## Evidence normalization

The first three runs used the same task, diff edit format, one attempt, seed 1701,
temperature 0.7, and top-p 1.0. Their prompt and candidate identities are recorded in
`observations.json`. The full r5 run used whole-file format and the three-task suite,
so it is supporting evidence rather than a matched comparison.

| Prompt condition | Size | Added/removed signal | Candidate behavior | First actionable failure |
| --- | ---: | --- | --- | --- |
| First demo baseline | 11,210 B | Concrete helper bodies and exact call shapes | Smallest candidate; retained the most required mechanisms | `to_time_t` declaration/placement and external qualification |
| Compile-safety revision | 11,627 B | Added placement cautions but removed concrete bodies | More churn and portable fallback rewrites | Fallback aliases, namespace mismatch, missing template declaration |
| W01-W38 revision | 17,379 B | Generic repository workflow plus task audit | Largest churn and incomplete migration | Unterminated include guard, namespace mismatch |
| Full r5 prompt | 10,484 B | Generic workflow without baseline implementation plan | No new production edit | Scope gate: no production change |

## Exact prompt defects

1. The W01-W38 block displaced concrete code shapes that the first candidate had
   followed successfully.
2. W31 and W35 instructed the model to compile and run probes, but this Aider lane
   provided no shell/tool turn before the model response. Those instructions were
   non-actionable prompt load.
3. The first prompt specified `detail` semantically but did not give an unambiguous
   lexical insertion anchor. The candidate placed helpers in a later `detail`
   reopening, after exported `gmtime` needed `to_time_t`.
4. The compile-safety revision warned about fallback functions but did not retain the
   exact helper bodies; the candidate retyped the fallback functions anyway.
5. The one-turn harness reported only final failure. It had no opportunity to return
   the first production-header diagnostic and repair the existing patch.
6. Demo-score wording encouraged textual mechanism matching even though executable
   compilation is authoritative. It is absent from the new model prompt.
7. Exact-substring mechanism checks can mark semantically present, line-wrapped code
   as missing. They remain diagnostic and never override build/test/probe outcomes.

## Selected ablation

The selected v3 prompt is `baseline + concrete shapes + structural locks`, with these
controlled removals and additions:

- Removed the generic W01-W38 and F01-F12 sections.
- Removed demo-score optimization language.
- Preserved the baseline objective, reproduction, invariants, 12 required changes,
  wrong-solution guards, helper bodies, and direct `gmtime(val)`/`localtime(val)` shapes.
- Added one exact insertion anchor before the `detail` close preceding
  `FMT_BEGIN_EXPORT`.
- Froze the fallback overloads and every preprocessor branch.
- Added a qualification rule for code inside versus outside `namespace detail`.
- Added a complete call-site ledger and an atomic-migration instruction.

The final prompt is in `final-prompt.md`; the executable contract is
`configs/public_pr_eval/public-pr-repo-eval-demo-fmtlib-v3.jsonl`.

## Harness change

Attempt 1 uses temperature 0.7. If it fails compilation, attempt 2 restores the same
Aider chat and repository, uses temperature 0.2, and receives only the first diagnostic
whose source location is the editable `include/fmt/chrono.h`. Absolute paths are
removed. Lines naming tests, probes, hidden output, or non-editable sources are not
included. When no safe editable-file diagnostic exists, the legacy status-only message
is used.

No Aider global system prompt was changed. That would add an unnecessary confound and
would affect unrelated tasks. The task-specific execution contract stays in the user
prompt; compiler feedback is a second user turn generated by the evaluator.

## Prospective ablation matrix

A real causal study should run independent clean snapshots with at least four seeds per
condition and identical model, adapter, diff format, and evaluator:

| Arm | Prompt | Repair | Purpose |
| --- | --- | --- | --- |
| A | Exact first baseline | None | Historical anchor |
| B | Baseline without score language | None | Isolate score wording |
| C | B plus eight structural locks and concrete shapes | None | Isolate prompt change |
| D | C | One sanitized compiler turn | Isolate harness repair effect |

Do not select by checklist text alone. Record patch apply, exact scope, compilation,
upstream chrono test, independent probe, mechanism diagnostics, candidate hash, and
all run controls. Repeated use of this public-PR task is diagnostic and cannot support a
clean-generalization claim.

## Validation completed

- Generated v3 JSONL is deterministic and digest-bound.
- Static prompt/scope/environment/hidden-asset validation passes.
- Compiler feedback privacy tests cover editable diagnostics, absolute-path removal,
  protected test suppression, and generic fallback.
- Twenty focused public-PR and compiler-guided tests pass, including an end-to-end
  mocked two-turn evaluator transition.
- Python compile and lint checks pass on the modified evaluator surfaces.
